# Patina

Patina — небольшой форк открытого сервера ID и ретрансляции
[`rustdesk/rustdesk-server`](https://github.com/rustdesk/rustdesk-server)
(`hbbs` и `hbbr`). С ним стандартный клиент RustDesk (версии 1.4.0 и новее,
проверялся с 1.5.0) с включённым параметром **«Использовать WebSocket»** может
быть управляемым устройством, даже если сервер доступен ему только через
`wss://<domain>:443`, например за обратным прокси nginx. Устройству не нужны
ни UDP 21116, ни прямой TCP 21115–21119.

Клиент не меняется. Патч затрагивает только `hbbs`; `hbbr` взят из upstream
без изменений.

> [!NOTE]
> Patina — независимый проект. Он не связан с проектом RustDesk и его
> владельцами и не одобрен ими. Название «RustDesk» здесь используется только
> для того, чтобы указать, с какой программой совместима Patina.

## Зачем нужен этот форк

Открытый `hbbs` из исходного проекта (upstream) регистрирует устройства только
по UDP 21116. По TCP или WebSocket он отвечает на `RegisterPk` кодом
`NOT_SUPPORT` и закрывает сокет, поэтому устройство, которому доступен только
WebSocket, так и не становится готовым к подключению. В upstream регистрация
через WebSocket считается функцией Pro-версии, и pull request, который её
добавлял, был закрыт
([rustdesk-server#657](https://github.com/rustdesk/rustdesk-server/pull/657)).
Связанные issues: [#677](https://github.com/rustdesk/rustdesk-server/issues/677)
(не работает, если UDP заблокирован) и
[#704](https://github.com/rustdesk/rustdesk-server/issues/704) (WebSocket
обрывается после 30 с простоя).

Клиентская часть уже работает, потому что её поддерживает RustDesk Server Pro.
Patina добавляет недостающую серверную часть и сохраняет минимальный diff
относительно upstream.

## Чем Patina отличается от upstream

Регистрация устройств через WebSocket по умолчанию выключена. При значении по
умолчанию `WS_REGISTER=N` Patina работает по протоколу upstream, с двумя
исключениями, которые действуют всегда: заголовки прокси принимаются только от
`TRUSTED_PROXY_CIDRS`, а для WebSocket-соединений действуют тайм-аут
рукопожатия 10 с, лимит сообщения 64 КиБ и ограничение `MAX_WS_CONN_PER_IP`.
Конфигурации upstream, которая полагалась на то, что `hbbs` доверяет
`X-Real-IP` от любого узла, после перехода на Patina нужна
`TRUSTED_PROXY_CIDRS`.

Также независимо от `WS_REGISTER`: `hbbs` не обращается к третьим сторонам по
своей инициативе. `hbbs` из upstream при запуске и затем ежедневно отправляет
на `api.rustdesk.com` проверку версии с отпечатком хоста. Patina делает это
только при `SOFTWARE_UPDATE_CHECK=Y`.

| Область | `hbbs` из upstream | `hbbs` из Patina с `WS_REGISTER=Y` |
| --- | --- | --- |
| Регистрация устройства через WebSocket | `RegisterPk` → `NOT_SUPPORT`, сокет закрывается | Те же проверки, что и для UDP, затем `RegisterPkResponse{OK}`; соединение остаётся открытым |
| Простаивающие WebSocket-соединения | Обрываются примерно через 30 с | Сервер каждые 12 с (`WS_KEEPALIVE_SECS`) отправляет пустой бинарный кадр; эхо от клиента обновляет регистрацию устройства |
| PunchHole, RequestRelay, FetchLocalAddr для WebSocket-устройства | Уходят по UDP и не доходят | Отправляются в WebSocket-соединение устройства |
| Статус «в сети» (`OnlineRequest`) через `/ws/id` | Нет ответа, устройства всегда показаны не в сети | Есть ответ; подключённое WebSocket-устройство показано в сети |
| Два управляющих устройства за одним NAT | Оба получают адрес `X-Real-IP:0`, адреса совпадают | Каждое получает уникальный адрес из `X-Real-Port` или идентификатора соединения |
| `X-Real-IP` / `X-Forwarded-For` | Принимаются от любого узла | Принимаются только от `TRUSTED_PROXY_CIDRS` (по умолчанию loopback); из `X-Forwarded-For` берётся последний узел цепочки |
| Ограничения | — | Лимит зарегистрированных WebSocket-устройств (`MAX_WS_PEERS`, по умолчанию 10000) и одновременных WebSocket-соединений с одного IP (`MAX_WS_CONN_PER_IP`, по умолчанию 64) |

Без изменений:

- Регистрация по UDP и пути через TCP 21115–21117 для существующих клиентов.
- Все исправления безопасности upstream вплоть до
  [`873230e`](https://github.com/rustdesk/rustdesk-server/commit/873230e35a8805de7fd057e7eb763c46f7a174ef),
  включая ограниченный `PUNCH_REQS`, лимит длины id в 253 байта и права 0600 на
  файл ключа. UDP `PunchHoleRequest` остаётся выключенным, как решили в
  upstream.
- `hbbr` и протокол ретрансляции.

## Известные ограничения

- К WebSocket-устройствам можно подключиться только через ретранслятор. Прямые
  (P2P) подключения и WebRTC для них не поддерживаются.
- Клиент, у которого отключён UDP, но не включён WebSocket (обычный TCP), по-прежнему
  не поддерживается. Ему нужен обмен ключами на стороне сервера, которого в Patina
  нет.
- Patina — не RustDesk Server Pro. В ней нет веб-консоли, адресной книги,
  учётных записей пользователей и других функций Pro-версии.

## Сборка

```bash
cargo build --release
```

В `target/release` появятся три исполняемых файла:

- `hbbs`: сервер ID (с патчем)
- `hbbr`: ретранслятор (из upstream)
- `rustdesk-utils`: утилиты командной строки (из upstream)

Многоэтапный [`Dockerfile`](Dockerfile) собирает те же файлы внутри Docker.
Он создаёт один минимальный образ для обоих серверов, который работает от
непривилегированного пользователя, с корневой файловой системой только для
чтения и без capabilities:

```bash
git submodule update --init libs/hbb_common
docker build -t patina:local .
```

Нужный сервер выбирается командой контейнера (`hbbs …` или `hbbr …`). См.
[deploy/docker-compose.example.yml](deploy/docker-compose.example.yml).

## Настройка

Флаги, переменные окружения и файлы конфигурации из upstream работают
по-прежнему; см. [docs/environment-variables.md](docs/environment-variables.md).
Patina добавляет в `hbbs` следующие переменные окружения:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `WS_REGISTER` | `N` | `Y` включает регистрацию устройств через WebSocket |
| `TRUSTED_PROXY_CIDRS` | только loopback | Узлы, которым разрешено передавать `X-Real-IP` / `X-Forwarded-For`. Добавьте CIDR сети Docker, если прокси работает в другом контейнере |
| `MAX_WS_PEERS` | `10000` | Максимальное число зарегистрированных WebSocket-устройств. Сверх него новые регистрации получают `SERVER_ERROR` |
| `MAX_WS_CONN_PER_IP` | `64` | Максимальное число одновременных WebSocket-соединений с одного IP-адреса клиента |
| `WS_KEEPALIVE_SECS` | `12` | Интервал пустого keepalive-кадра, 5–20 с. Клиенту сервер сообщает `keep_alive`, втрое больший этого значения |
| `SOFTWARE_UPDATE_CHECK` | `N` | `Y` возвращает ежедневную проверку версии из upstream, которая отправляет отпечаток хоста на `api.rustdesk.com` |

Подробности — в [docs/ws-registration.ru.md](docs/ws-registration.ru.md).

Запускайте `hbbs` с `-r <domain>`. Тогда управляющие устройства направляются к
ретранслятору через тот же домен. Для WebSocket-устройств `-r` обязателен:
`hbbs` передаёт WebSocket-устройству `RequestRelay`, только если указанный в
нём ретранслятор есть в `-r`.

## Безопасность

Устройства, которые регистрируются на сервере Patina, часто принадлежат другим
людям. Для регистрации через WebSocket Patina выполняет те же проверки владельца
id, uuid и ключа, что upstream выполняет для UDP, и привязывает id только к тому
соединению, через которое он был зарегистрирован. Модель угроз описана в
[docs/ws-registration.ru.md](docs/ws-registration.ru.md).

По умолчанию ни один из серверов не обращается к третьим сторонам: нет ни
проверки версии, ни телеметрии. `hbbs` только разрешает имена из `-r` и
проверяет доступность ретрансляторов, если в `-r` их больше одного. `hbbr`
ничего не открывает. Аудит и проверка с захватом пакетов
([tests/egress-check.sh](tests/egress-check.sh)) описаны в разделе
[«Исходящие соединения»](docs/ws-registration.ru.md#исходящие-соединения).

Владельцам устройств стоит также включить в клиенте двухфакторную
аутентификацию, подтверждение нажатием и белый список ID. Как это сделать,
описано в [deploy/client-settings.ru.md](deploy/client-settings.ru.md).

## Лицензия и исходный код

Patina распространяется по лицензии GNU Affero General Public License v3.0,
как и upstream. См. [LICENSE](LICENSE). Уведомления об авторских правах
upstream сохранены.

Раздел 13 AGPL требует, чтобы пользователям, которые взаимодействуют с
изменённой версией программы по сети, был предложен её Соответствующий
исходный код. Исходный код Patina опубликован по адресу
<https://github.com/gleruzh/patina>. Если вы запускаете Patina:

- используйте неизменённую версию с тегом либо так же опубликуйте свои
  изменения под AGPL-3.0;
- дайте людям, чьи устройства подключаются к вашему серверу, ссылку на
  исходный код той версии, которую вы запускаете, например вместе с
  настройками клиента, которые вы им отправляете.

## Указание авторства

- [`rustdesk/rustdesk-server`](https://github.com/rustdesk/rustdesk-server):
  исходный код upstream, © open-trade / разработчики RustDesk, AGPL-3.0.
  Patina основана на коммите upstream `873230e35a8805de7fd057e7eb763c46f7a174ef`.
- [`ymg2006/rustdesk-server`](https://github.com/ymg2006/rustdesk-server)
  (AGPL-3.0): устройство приёмников (sink) WebSocket с ключом из id узла и
  идентификатора соединения (побеждает новейшее, очистка с проверкой
  владельца), маршрутизация PunchHole, FetchLocalAddr и RequestRelay в
  WebSocket-приёмник и `TRUSTED_PROXY_CIDRS`.
- [`bropines/rustdesk-server`](https://github.com/bropines/rustdesk-server/tree/rdpanel),
  ветка `rdpanel` (AGPL-3.0): устройство keepalive — пустой бинарный кадр
  примерно каждые 12 с, время регистрации обновляется при каждом эхо-ответе.

Patina заимствует у этих форков идеи; код из них не копировался. Что
сознательно не взято, перечислено в
[PATCHES.ru.md](PATCHES.ru.md#указание-авторства).
