# Настройка клиента для устройств, работающих только через WebSocket

С этими настройками стандартный клиент RustDesk (версии 1.4.0 и новее,
проверялся с 1.5.0) регистрируется на сервере Patina и принимает удалённые
подключения, даже если сервер доступен ему только через `wss://<domain>:443`.
В примерах используется домен `patina.example.com`; замените его своим.

Инструкция рассчитана на владельцев устройств: специальных знаний не нужно,
достаточно повторить шаги по порядку. Названия кнопок и пунктов меню приведены
так, как они выглядят в русском интерфейсе RustDesk 1.5.0, а в скобках указано
английское название — на случай, если программа у вас на английском. Названия
параметров и надписи интерфейса взяты из исходного кода клиента 1.5.0
(`flutter/lib/consts.dart`, `desktop_setting_page.dart`, мобильные
`settings_page.dart` и `server_page.dart`, `src/server/connection.rs`,
`hbb_common/src/websocket.rs`, `src/lang/ru.rs`).

> **Внимание: «Сервер API» должен быть `https://<domain>`.** Клиент использует
> шифрованное соединение `wss://`, только если адрес сервера API начинается с
> `https`. Если оставить поле пустым или указать `http://…`, клиент попытается
> подключиться по незашифрованному `ws://<domain>/ws/id` на порт 80. Прокси
> перенаправит такой запрос на HTTPS, рукопожатие WebSocket не состоится, и
> устройство так и не появится в сети. Если в поле «Сервер ID» указать
> IP-адрес вместо домена, клиент сразу пойдёт на `ws://IP:21118`, а этот порт
> не открыт наружу, поэтому подключения тоже не будет. Всегда указывайте домен
> в поле «Сервер ID» и `https://<domain>` в поле «Сервер API».

Перед началом:

- Проверьте версию: «Настройки» (Settings) → «О приложении» (About) →
  «Версия» (Version). Скачивайте RustDesk только с официальной страницы
  [github.com/rustdesk/rustdesk/releases](https://github.com/rustdesk/rustdesk/releases).
- Получите у администратора сервера домен, ключ сервера и список ID, которым
  разрешено подключаться к вашему устройству.

## Обязательные настройки

«Настройки» (Settings) → «Сеть» (Network) → **«ID/Ретранслятор»** (ID/Relay
Server):

| Поле | Значение | Ключ параметра |
|---|---|---|
| «Сервер ID» (ID Server) | `patina.example.com` | `custom-rendezvous-server` |
| «Ретранслятор» (Relay Server) | `patina.example.com` | `relay-server` |
| «Сервер API» (API Server) | `https://patina.example.com` | `api-server` |
| `Key` | открытый ключ сервера (см. ниже) | `key` |

«Настройки» (Settings) → «Сеть» (Network) → **«Использовать WebSocket»**
(Use WebSocket): включено (`allow-websocket=Y`).

На Android откройте вкладку **«Настройки»** (Settings): там же находятся пункт
**«ID/Ретранслятор»** (ID/Relay Server) с четырьмя полями и переключатель
**«Использовать WebSocket»** (Use WebSocket).

Пошагово:

1. **Windows, macOS, Linux.** В главном окне RustDesk нажмите значок «⋮»
   справа от вашего ID (подсказка «Настройки», Settings) и слева выберите
   вкладку «Сеть» (Network). Если пункты на вкладке серые, нажмите
   «Разблокировать сетевые настройки» (Unlock Network Settings): система может
   попросить пароль администратора компьютера или PIN-код, если он задан в
   RustDesk.

   **Android.** Внизу экрана откройте вкладку «Настройки» (Settings); нужные
   пункты находятся в разделе «Настройки».
2. Нажмите «ID/Ретранслятор» (ID/Relay Server), заполните четыре поля по
   таблице выше и нажмите «ОК» (OK). Поле `Key` и в русском интерфейсе
   называется `Key`. Вставляйте ключ целиком, без пробелов в начале и в конце.
3. Там же включите переключатель «Использовать WebSocket» (Use WebSocket).
4. Вернитесь в главное окно (на Android — на вкладку «Демонстрация экрана»,
   Share screen). В течение 30 секунд должен появиться статус «Готов» (Ready):
   на компьютере — в левом нижнем углу окна. На Android, если служба не
   запущена, нажмите «Запустить службу» (Start service) и дайте разрешения,
   которые запросит система.

Если администратор прислал готовую строку конфигурации, её можно не вводить
вручную: скопируйте строку, откройте окно «ID/Ретранслятор» и нажмите значок
«Импортировать конфигурацию сервера» (Import server config). Проверьте, что
поля заполнились по таблице, и нажмите «ОК» (OK). «Использовать WebSocket» всё
равно нужно включить отдельно.

Зачем нужно каждое поле:

- **«Сервер ID» и «Ретранслятор»**: введите только домен, без порта и без
  `https://`. В режиме WebSocket клиент направляет трафик сервера ID на
  `<host>/ws/id`, а трафик ретранслятора — на `<host>/ws/relay` (`check_ws`).
  Если указать IP-адрес, клиент подключится по незашифрованному
  `ws://IP:21118`, в обход прокси и TLS, поэтому всегда указывайте домен.
  `hbbs` запущен с `-r patina.example.com`, поэтому адрес ретранслятора, который
  выдаёт сервер, тоже превращается в `wss://patina.example.com/ws/relay`.
- **«Сервер API»**: клиент использует `wss://`, только если `api-server`
  начинается с `https`. Иначе он подключается по незашифрованному `ws://`
  (см. предупреждение в начале). Сервера API по этому адресу нет: на любой
  запрос к `/api/` прокси отвечает `{}`. Так и должно оставаться: ответ на
  `/api/heartbeat` может передавать параметры конфигурации (`strategy`) и
  разрывать сеансы (`disconnect`) на всех устройствах, которые используют этот
  сервер.
- **`Key`**: содержимое файла `id_ed25519.pub` из тома данных `hbbs` (одна
  строка base64). Сервер отклоняет клиентов без ключа: `hbbr` запущен с
  `-k _`, а `hbbs` по умолчанию требует ключ.
  Управляющее устройство тоже использует ключ: им оно проверяет подписанный
  открытый ключ устройства в ответе ретранслятора. В режиме WebSocket клиент
  не выполняет обмен ключами (KeyExchange) с сервером и защищает этот участок
  соединения только с помощью TLS, поэтому нужны и ключ, и действительный
  сертификат.
- **«Использовать WebSocket»**: когда параметр включён, устройство держит
  постоянное соединение `wss://…/ws/id`, регистрируется через него и принимает
  входящие сеансы через `wss://…/ws/relay`. Рядом с переключателем клиент
  показывает «ПРИМЕЧАНИЕ: в OSS-сервере RustDesk эта функция отсутствует.»
  (NOTE: RustDesk server OSS doesn't include this feature.) Patina эту функцию
  поддерживает. С включённым WebSocket работают только подключения через
  ретранслятор (без прямых P2P-подключений и без WebRTC).

Сертификат должен быть действителен для домена, и устройство должно ему
доверять (сертификату Let's Encrypt от SWAG доверяют). Параметр
`allow-insecure-tls-fallback` («Разрешать небезопасные TLS», Allow insecure TLS
fallback) — только для тестовых стендов. На настоящих устройствах никогда его
не включайте.

### Настройка из командной строки

Этот раздел для администраторов; владельцу устройства, который настроил всё в
окне программы, он не нужен.

На установленном клиенте выполните команды от имени root или администратора.
Ключи параметров одинаковы во всех ОС:

```sh
rustdesk --option custom-rendezvous-server patina.example.com
rustdesk --option relay-server patina.example.com
rustdesk --option api-server https://patina.example.com
rustdesk --option key '<contents of id_ed25519.pub>'
rustdesk --option allow-websocket Y
```

`rustdesk --option <key>` без значения выводит текущее значение параметра. В
Windows используйте `rustdesk.exe` из папки установки.

## Рекомендуемая защита

Эти устройства принадлежат другим людям, поэтому, кроме пароля, включите
следующие настройки.

### Двухфакторная аутентификация

«Настройки» (Settings) → «Безопасность» (Security) → **«2FA»** →
«Использовать двухфакторную аутентификацию» (Enable two-factor
authentication).

1. **Windows, macOS, Linux.** Откройте вкладку «Безопасность» (Security). Если
   пункты серые, нажмите «Разблокировать настройки безопасности» (Unlock
   Security Settings). В блоке «2FA» нажмите «Использовать двухфакторную
   аутентификацию».
2. Отсканируйте QR-код приложением-аутентификатором (например, Google
   Authenticator, Microsoft Authenticator или Authy) и введите шестизначный
   код, который оно покажет.

После этого для каждого нового входящего сеанса, кроме пароля, нужен код из
приложения. «Включение доверенных устройств» (Enable trusted devices)
позволяет управляющим устройствам, которые уже прошли 2FA, больше не вводить
код. Оставьте эту настройку выключенной, если только одно и то же управляющее
устройство не подключается очень часто.

2FA включается только в окне программы: параметра `--option` для неё нет. На
Android используйте раздел **«2FA»** на вкладке **«Настройки»** (Settings).

### Подтверждение нажатием

«Настройки» (Settings) → «Безопасность» (Security) → **«Пароль»** (Password) →
«Принимать сеансы нажатием кнопки» (Accept sessions via click,
`approve-mode=click`).

Человек у устройства должен сам принять каждый сеанс кнопкой «Принять»
(Accept) в окне управления подключениями, поэтому к компьютеру без присмотра
подключиться нельзя. «Принимать сеансы по паролю и нажатию кнопки» (Accept
sessions via both, `approve-mode` пустой) принимает сеанс и по паролю, поэтому
этот режим подходит для компьютеров без присмотра. Везде, где рядом с
устройством есть человек, используйте режим «только нажатием кнопки».

```sh
rustdesk --option approve-mode click
```

На Android откройте вкладку **«Демонстрация экрана»** (Share screen), нажмите
меню «⋮» в правом верхнем углу и выберите «Принимать сеансы нажатием кнопки»
(Accept sessions via click).

### Белый список ID

«Настройки» (Settings) → «Безопасность» (Security) → **«Использовать белый
список ID»** (Use ID whitelisting; подсказка «Только ID из белого списка могут
получить доступ к моему устройству.», параметр `id-whitelist`).

В открывшемся окне «Список разрешённых ID» (ID whitelisting) введите ID
управляющих устройств, которым разрешено подключаться, через запятую, и
нажмите «ОК» (OK). Можно использовать подстановочный знак `*`.

```sh
rustdesk --option id-whitelist '123456789,987654321'
```

На Android: вкладка **«Настройки»** (Settings) → раздел **«Демонстрация
экрана»** (Share screen) → **«Использовать белый список ID»** (Use ID
whitelisting). Список ID вводится так же, как на компьютере.

Клиент сверяет список с ID, который управляющее устройство сообщает о себе
само (`check_id_whitelist`), поэтому белый список не заменяет аутентификацию.
Он сужает круг ID, которые вообще могут пробовать пароль, а неудачные попытки
ограничиваются по адресу источника. Используйте его вместе с 2FA или
подтверждением нажатием, а не вместо них.

Более старая настройка **«Использовать белый список IP»** (Use IP
Whitelisting, параметр `whitelist`) проверяет IP-адрес управляющего
устройства. У WebSocket-устройства все сеансы идут через ретранслятор, поэтому
проверяется тот адрес управляющего устройства, который записал `hbbs`. Если у
управляющих устройств динамические или общие адреса, такой список трудно
поддерживать в актуальном состоянии, поэтому белый список ID обычно удобнее.

## Что не меняется

- Клиенты, которые не используют WebSocket, работают как прежде, через UDP
  21116 и TCP 21115–21117. Управляющее устройство в режиме UDP может
  подключиться к WebSocket-устройству, а управляющее устройство в режиме
  WebSocket — к UDP-устройству; в обоих случаях через ретранслятор.
- Статус «в сети» в адресной книге работает и для WebSocket-устройств (`hbbs`
  отвечает на `OnlineRequest` через `/ws/id`).

## Если не работает

- **Устройство не появляется в сети и не показывает статус «Готов» (Ready).**
  - Проверьте, что в поле «Сервер API» указано ровно `https://<domain>` и что
    «Использовать WebSocket» включён.
  - Проверьте, что в поле «Сервер ID» указан домен, а не IP-адрес.
  - На сервере (для администратора): в выводе `docker logs rustdesk-hbbs`
    должен быть `patina.example.com` в `relay-servers=[...]`, а в журнале доступа
    прокси — запросы `GET /ws/id` с кодом 101.
- **Ошибки TLS или сертификата.** Устройство должно доверять сертификату для
  `<domain>`. Проверьте часы на устройстве и то, что сертификат SWAG включает
  этот поддомен. Простая проверка: откройте `https://<domain>` в браузере на
  самом устройстве. Страница «404 Not Found» — это нормально, а предупреждение
  о сертификате — нет. Не обходите проблему с помощью
  `allow-insecure-tls-fallback`.
- **«Несоответствие ключей» (Key mismatch) или подключение обрывается сразу
  после начала.** Поле `Key` должно в точности совпадать с содержимым
  `id_ed25519.pub` на сервере, без лишних пробелов и переносов строк.
- **Подключение работает, но медленно.** WebSocket-устройства всегда
  подключаются через ретранслятор, это ожидаемо. Прямые P2P-подключения и
  WebRTC в этом режиме недоступны.
- **Изменился ID устройства.** Клиент создаёт новый ID, только если сервер
  ответил `UUID_MISMATCH`, а это происходит, когда этот ID уже зарегистрировал
  другой компьютер. Перезапуск сервера, прокси или устройства ID не меняет.
  Если ID всё же изменился, сообщите новый ID администратору.
- **«Ваш ID заблокирован удалённым устройством» (Your ID is blocked by the
  peer).** ID управляющего устройства нет в белом списке ID на устройстве.

## Исходный код сервера

Сервер — Patina, изменённая версия rustdesk-server под лицензией GNU AGPL v3.
Как требует §13 AGPL, полный исходный код сервера, к которому вы подключаетесь,
доступен по адресу <https://github.com/gleruzh/patina>.
